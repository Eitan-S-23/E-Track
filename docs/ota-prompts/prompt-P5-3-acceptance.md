# P5-3 文档收尾验收 Spec

task_id: P5-3

## 任务类型

`ACCEPTANCE`

## Readiness 引用

唯一任务状态见 `PLAN-OTA-EXEC.md` readiness 矩阵的 `P5-3` 行。本文件不得另行维护该状态。本文件定义文档收尾的验收边界，不宣告风险项已关闭。

## 验收范围

在 P1-P5 技术结论稳定后，完成 bootstrap 手册、用户升级操作手册、运营发布/撤回/恢复说明、维护者故障速查、风险台账和 AGENTS.md OTA 防坑条目；逐项关闭 `PLAN-OTA.md` §9 开口项或明确转入 v2，并验证文档命令、链接、名称、合同引用和能力边界与最终实现一致。

## 非目标

- 不以改文档掩盖未完成产品实现、失败验收或尚未独立复核的候选规范。
- 不在收尾卡修改冻结 binary contract、任务结构或生产行为。
- 不复制完整 schema/字节表到多个手册。
- 不创建与产品无关的泛化流程文档。

## 前置依赖

- `PLAN-OTA-EXEC.md` 既有 P5 阶段门槛：P1-P4 完成；P5-1/P5-2 的最终结论可引用。
- 所有共享合同和需要对外操作的决策已冻结或明确转 v2。
- 资产保留与删除治理见 `OTA-XC-D1-RETENTION` 和 `OTA-XC-R2-IMMUTABILITY`；相关条款完成独立复核、冻结并具备审批证据后，才能关闭运营风险项。

## 权威合同

- `OTA-XC-SCOPE`
- `OTA-XC-RELEASE-CLI`
- `OTA-XC-ADMIN-RETRACT`
- `OTA-XC-ADMIN-STOP`
- `OTA-XC-SECRETS`
- `OTA-XC-CANCEL-RECOVERY`
- `OTA-XC-SECURITY`
- `PLAN-OTA.md`、`PLAN-OTA-EXEC.md` 和全部最终冻结 OTA 合同

## 现有组件和代码入口

- `docs/ota-bootstrap-jlink.md`、现有 OTA exec notes/acceptance reports。
- 根 `AGENTS.md` 的 build/J-Link/RTT/SD/Simulator 维护经验。
- `PLAN-OTA.md` §9 风险与开口项。
- P4 admin/CI 操作界面、Flutter OTA UI、MCU recovery/SD/BLE 路径。

## 输入输出与调用方向

- 输入：最终冻结合同、生产代码入口、实际命令、最终 artifact 名、P5 证据、已裁定决策。
- 输出至少包括：维护者 bootstrap/runbook、用户升级手册、运营发布/撤回/停发/恢复手册、风险台账、AGENTS.md 精炼红线和链接索引。
- 共享字段/协议只链接权威合同；手册保存角色化步骤和故障处理，不另建真相源。

## 状态机与生命周期所有者

- 产品/合同 owner 保持规范真相；文档 owner 负责可发现性和操作准确性。
- 风险项只允许“已由证据关闭”或“带 owner/原因/目标版本转 v2”，不得无依据删除。
- 文档中的发布/撤回/恢复流程必须按实际角色和审批顺序描述。

## 错误、超时、重试、取消、恢复与幂等

- 所有操作手册必须写明失败后的停止点、可重试条件、不可重放动作和恢复/回退路径。
- 撤回不得写成设备降级，recovery 必须写明物理在场和完整校验边界。
- secret 配置示例只列名称/占位符，禁止真实值。
- 重复执行命令的幂等性或副作用必须与最终 CLI/admin 合同一致。

## 允许修改范围

- `docs/` 下 OTA/用户/运营/维护文档和最终索引。
- 根 `AGENTS.md` 的 OTA 维护期防坑条目。
- `PLAN-OTA.md` §9 或任务看板只在其治理规则和独立审查授权允许时做最终关闭；冻结文件需走正式修订流程，不能由本卡直接改。
- 文档链接/命令的轻量静态测试。

## 禁止修改与生产红线

- 禁止改生产源码、workflow、D1 或 UI 来让文档成立。
- 禁止修改冻结合同而不升版/走审批。
- 禁止记录 API key、token、AES key、签名 URL 或账户敏感信息。
- 禁止写“全部通过”但没有链接到正式证据。
- 禁止把 v2 风险描述成 v1 已保证。

## 证据分类与采集

- Production：文档所指向的最终路径、CLI/API/UI 名称和 artifact。
- Validation：命令 dry-run/静态链接检查、截图、示例输出和 P5 报告引用。
- Governance：合同版本/成熟度、决策闭合记录、文档评审和 CI。
- 每个手册步骤需可追溯到权威条款或真实组件入口。

## 判定规则

- 所有必需文档存在、链接有效、命令/名称与最终实现一致。
- §9 每个开口项都有闭合证据或明确 v2 owner/原因/触发条件。
- 用户手册可由不读源码的用户完成升级/错误处理；维护手册可由 agent 定位构建、发布、J-Link/RTT 和恢复。
- AGENTS.md 只收录经实战验证、可复用且高风险的红线，不复制长篇项目历史。

## 结果分类

使用 `PASS`、`PRODUCT_FAIL`、`EVIDENCE_GAP`、`ENV_BLOCKED`、`HARNESS_FAIL`。未完成实现导致的文档缺口是前置依赖问题，不得靠措辞降级为 PASS。

## 失效条件

- 文档引用未冻结候选却写成最终规则。
- 示例命令指向旧文件名、旧 schema、旧路径、AC5 OTA 产物或不存在入口。
- 风险项被删除但无证据/owner/决策。
- 文档生成后相关生产接口又发生变化且未重审。

## 必须新增或调整的测试

- Markdown 链接、相对路径、命令中的关键文件存在性检查。
- 资产名/API path/secret 名称与共享合同/实现一致性检查。
- 冻结合同链接唯一、禁止复制 byte/DDL/schema 的轻量检查。
- AGENTS.md OTA 条目与最终 build/J-Link/发布事实的人工+静态复核。

## 完成判据

- bootstrap、用户升级、运营和维护文档齐全并经目标读者独立走查。
- §9 无悬空项；转 v2 项均有 owner、原因和触发条件。
- 所有链接/静态测试通过，示例不包含 secret 或过时入口。
- P5-1/P5-2 最终报告和版本化 contract/evidence 可从文档索引访问。

## 停止条件

- P1-P4 或关键 P5 验收未完成时停止最终收口，只可记录待办，不伪造完成态。
- 保留策略或其他影响操作手册的候选规范尚未独立复核并冻结时，停止对应章节定稿。
- 冻结文件需要修改但无正式修订授权时登记建议，不原位修改。
- 真实命令/界面与合同冲突时回实现/治理流程，不改文档掩盖。

## 正式 acceptance contract 前置

只有在最终文档集合、风险台账字段、链接检查和目标读者走查方法稳定，并且所有引用合同版本固定后，才创建 P5-3 的版本化验收合同；合同应绑定文档 manifest，而不是复制全文。

## 后续证据

文档 manifest、链接/命令检查、目标读者走查记录、风险关闭矩阵、AGENTS.md diff、最终文档索引和治理 CI run。

## Luna 可自行决定

文档分册、标题、截图布局、索引结构和静态链接检查实现；不得自行关闭风险、批准合同或改变产品能力。

## 阻断性决策

- 无。全部相关决定已由用户批准；执行要求以“权威合同”章节引用的冻结 OTA-XC 条款为准。
