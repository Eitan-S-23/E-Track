# 执行会话提示词模板（派给实现 agent）

> 用途：把一张看板任务卡冻结成一份可直接派发的实现提示词。
> 撰写者：**非实现会话**（强模型/验收侧）。执行者：实现会话（可用较轻模型）。
> 参考实例：`docs/ota-prompts/prompt-P1-7-implementation.md`（本模板即从该文件抽取骨架）。
>
> 本文件分两部分：
> - **Part A 撰写检查表** —— 给撰写者看，**禁止复制进派发的 prompt**。
> - **Part B prompt 骨架** —— 复制到 `docs/ota-prompts/prompt-<卡ID>-implementation.md`
>   后逐项填空。派单提示词是规范性文件，必须落在 `docs/ota-prompts/`（纳入 Governance
>   manifest 与 Acceptance Governance workflow），**不得放在 `.claude/`**。

---

# Part A：撰写检查表（不要复制到派发文件）

## A.1 只冻结「验收抓不住」的决策

判据：**执行侧做错之后，验收侧能否在合同判据上直接看出来？**

- 看不出来 → 必须写进 prompt 并给理由。
- 一眼看出来 → 不要写。写了只会稀释红线，让 prompt 从 260 行涨到 600 行。

必须冻结的六类：

| 类别 | 为什么验收抓不住 | 实例 |
|---|---|---|
| 1. 顺序 / 时序硬约束 | 编译通过、功能"正常"，只有专测才暴露 | `system_clock_config()` 必须在 `boot_platform_init()` 第一行，否则 `SysTick_Config()` 取到旧 `system_core_clock`，boot 毫秒计时压缩 36 倍，`BOOT_RECOVERY_HOLD_MS=3000` 实际变 83 ms，破坏「按住 ≥3s」契约 |
| 2. 用哪个组件 / 复用哪条既有链 | 执行侧最典型失败是另写一套；返工成本最高 | P2-3 必须复用 P2-2 的解密/解压/candidate 写入链、必须用 P0-5 安全 API、40B 内层头禁止 `struct memcpy`；UI 侧禁 `shadow_*` / `lv_draw_*` / `LV_EVENT_DRAW_POST` |
| 3. 语义选择 + 理由 | 只给结论会被"优化"掉 | App 侧写「确保 PD2 为高」而非「跳过整段」：代价相同，但异常进入路径下后者会断电 |
| 4. 已有证据、不必重做的实验 | 不写就会去做危险动作 | PD2 低=断电由 `HAL_Power.cpp` 的关机动作自证，**无需另做断电实验** |
| 5. 预算与判定口径 | 执行侧会误判自己没达标，转而去动红线 | `≤1.5s` 里有 1000 ms 是刻意防抖；实测 1.3~1.5 s **属于通过**，不要去砍 SHA 校验 |
| 6. 红线 + 违反后果 + 正确通道 | 否则会就地改契约继续实现 | 契约矛盾 → 置「阻塞」+ 看板 §9 登记 + 停止 |

**不要写**：函数如何切分、变量命名、日志文案、局部循环写法。

## A.2 细节不可穷举，用停止条件兜底

P1-7 的 prompt 写到 260 行，实现会话依然在真机阶段撞上 prompt 完全没预料的缺陷 C
（PA15 既是唯一物理开机键又是 boot 恢复键，落入无超时 YMODEM 循环），并把设备陷进
BCB ROLLBACK 自锁事故。**真机失效模式天然不可穷举**，所以 Part B §6 的停止条件是
必填项，不是可选项。

## A.3 撰写完成前自检

- [ ] 每条红线都写了**违反后果**，不只是"禁止"
- [ ] 每个「实测」基线都标了来源，推断值明确标注为推断（P1-7 §3.4 的做法）
- [ ] 组件/复用链已点名到 `file:line` 或具体 API
- [ ] 停止条件已填，且包含"改范围外文件"与"未列出的失效模式"两项
- [ ] 交付清单要求了证据矩阵格式，不是散文式证据
- [ ] 引用的构建/烧录路径与 `AGENTS.md` 现行一致
      （生产走 GCC；AC5 map 用 `Listings-App-AC5\X-Track-App-AC5.map`，
      **不得**写已废弃的 `Listings\X-Track.map`）
- [ ] prompt 里没有任何 `git commit/push/merge` 指令

```text

> 落盘时间 <YYYY-MM-DD>。实现会话直接读本文件开工，不需要用户复述背景。

## 0. 你的身份与规约（先读，违反即作废）

你是 **<卡ID> 的实现会话**。本仓库 `AGENTS.md` 的「OTA 执行规约」对你强制生效：

1. **先读看板再动手**：`PLAN-OTA-EXEC.md` 是唯一任务与状态源。开工前先把 <卡ID>
   状态改为「进行中」并写认领标识，**只改卡内「范围」列出的文件**。
2. **契约只读**：`PLAN-OTA.md` 与 `docs/ota-binary-contracts.md` 冻结。发现矛盾或
   不可实现 → 把 <卡ID> 置「阻塞」+ 在看板 §9 变更登记表登记，然后停止。
   **禁止就地修改契约继续实现**。
3. **完成必须附证据**：命令 + 关键输出、产物路径 + 时间戳、哈希。长输出落盘
   `docs/ota-exec-notes/<卡ID>-implementation-evidence-<YYYY-MM-DD>.md`。
   **你不自验收** —— 验收由另一个非实现会话执行。
4. **research 落盘**：编码前的检索/分析结论写进上面那个证据文档，不许只留在对话里。
5. **不提交**：禁止 `git commit` / `push` / `merge`，由主会话收口。
6. **收尾**：结束前回写 <卡ID> 卡状态，并在看板 §10 会话日志追加一行。
7. **绝对禁止** `git checkout -- <file>` / `git restore`：本 worktree 的未提交内容
   是唯一副本，覆盖即永久丢失。

全局准则：**一切输出、文档、注释、日志、提交信息用简体中文**（代码标识符除外）。

## 6. 停止条件（必须遵守，不得自行扩范围）

出现以下任一情况：**落盘现象 → 停止 → 等裁决**，不要自己决定怎么办。

1. 需要改卡内「范围」之外的文件。
2. 遇到本 prompt 未列出的失效模式（新缺陷、新死锁、新触发条件）。
3. 同一验证项连续 3 次失败。
4. 真机进入无法用本 prompt 所述手段恢复的状态。
5. 发现红线之间互相矛盾，或红线与实测冲突。

## 8. 真机自测（J-Link；正式验收由非实现会话重跑）
```
