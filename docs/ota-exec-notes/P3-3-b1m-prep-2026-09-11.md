## 3. 本机环回中央：**不可行**（如实记录，不写「永远无法实测」）

- 外设侧正常广播（`advertising_started advertisement_status=2`、
  `advertisement_status_changed status=2 error=0`）。
- 同机 `bleak` 扫描 12s（另一次 8s）共发现 8–9 个设备，**无一**含服务 UUID
  `0000fff0-...`，也不含本机名称/本机地址；全部为外部设备（AJBLE94、两枚 `0000a5e0` 等）。
- 结论：Windows 的本地适配器扫描不报告本机 GATT server 的广播（自过滤），
  **PC 环回不能替代手机作为中央端**。中央侧判据必须由手机（或另一台外部中央）提供。

## 4. 两项本机异常（必须由中央侧实测定性，不得据此改判据）

### 4.1 `GattLocalCharacteristic.characteristic_properties` 回读**系统性丢失 WRITE 位**

判别实验（`.cache/p3-3-t1b/prop_discriminate.py`）：

| 请求属性 | 回读 | 差值 |
| --- | --- | --- |
| `READ\|WRITE` = 10 | 2 | −8 |
| `WRITE` = 8 | 0 | −8 |
| `WRITE` = int(8) | 0 | −8 |
| `READ\|WRITE\|NOTIFY` = 26 | 18 | −8 |

已排除：赋值形式（枚举 / int 同结果）、注册写处理器前后（`prop_after_handler.py`：注册前后
均 0）、`static_value`（已设置，可回读非空）、权限级别（`ENCRYPTION_REQUIRED` 能正确回读 2）。
另：广播启动后回读仍为 0（`b1m-adv-probe` 的 `properties_after_advertising=0`）。

两种可能，**本机无法定性**：
（a）本机该属性 getter 的投影/掩码问题，特征实际可写；
（b）特征对中央真的不可写。
判定方式只有一个：中央侧（手机）发现结果中该特征的 properties 是否含 `write`。
若不含 → A 路径在**发现阶段**即受阻，按操作单 §7.6 止损，不消耗其余策略额度。

### 4.2 `stop_advertising()` 后 1s 内 `advertisement_status` 仍读回 2

`b1m-adv-probe` 中 `advertising_stopped advertisement_status=2`（等待 1s 后回读），
且未观察到新的 `advertisement_status_changed` 事件。已把停止后的等待放宽到 3s 复测；
但**进程退出会释放 provider**，故不以该读数声称「仍在广播」，也不以它声称「已停止」——
两种口径都不成立，只有「调用过 `stop_advertising()` 且进程已退出」是确定事实。
