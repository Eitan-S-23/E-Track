## Implementation

- Standard @aws-sdk/client-s3 3.1152.0 is pinned in the existing worker package.
  The storage adapter keeps the original head/conditional-create/full-readback
  algorithm, sends If-None-Match on PUT and If-Match on GET, and never retries
  unconditionally. Credentials and endpoint are explicit; no default credential
  provider or control-plane token is used. SDK errors are projected without
  response bodies, URL, signatures or values.
- New authenticated POST /api/ci/firmware/preflight uses the target Worker's
  own DB binding. Auth, strict envelope and environment validation precede DB
  access. A shared verifyMonotonic retains the three original queries. No SQL,
  account, bucket or database selectors are accepted. It writes no rows/objects.
  Registration's existing validation/transaction logic is unchanged except reuse
  of the same bearer-auth helper. Preflight is not a physical-binding attestation.
- Both environments and the check-only entry consume the same new chain.
  TRACE_R2_ACCESS_KEY_ID / TRACE_R2_SECRET_ACCESS_KEY replace the old CF API token;
  rehearsal uses independently prefixed secrets. Old D1 variables are no longer
  mapped. AES, deploy/HMAC and existing resources are not changed on platforms.
- Release evidence identifies publicationProtocol=s3-worker-preflight-v1 and
  the preflight result. Promotion rejects old-chain evidence even if its old
  digest is supplied as approved. metadataSha256 uses existing canonical JSON
  plus LF bytes; r2Verified=true is an identity projection, not upload evidence.

Current shared contracts and the existing Specs are synchronized, not replaced
by another Spec. P41-CF-CREDENTIAL-02 remains a historical test-chain exception;
no production account-level permission has been granted.
