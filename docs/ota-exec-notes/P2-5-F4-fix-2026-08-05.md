# P2-5 F4 修复实现证据(2026-08-05)

## 缺陷 F4 概述

设备进入 SD 固件升级页,点击"文件管理"按钮后黑屏重启,复位原因实测
`Reset: NRST WDT`(两次独立启动复现,逐字一致)。根因:App 侧 10s IWDG
(`HAL_Config.h:222-224`,`HAL.cpp:141-142` 无条件启动)唯一由主循环
`HAL_Update()` 喂(`HAL.cpp:157-160`),而 `LoadFiles()`
(`FirmwareUpdate.cpp:567-591`)在 LVGL 回调内同步全目录扫描,循环上界
`rowCount < ROW_MAX` 因被过滤条目(隐藏项/非 .etu/路径超长)一律
`continue` 不增 `rowCount` 而失效,扫描 >10s 喂狗断供复位。

## 修复方案

方案 1(限制遍历总数)+ 方案 2(扫描期喂狗)组合,符合 prompt S3.1 倾向。

### 改动文件

1. `USER/App/Pages/FirmwareUpdate/FirmwareUpdate.h`
   - `ROW_MAX` 枚举新增 `SCAN_MAX = 256`:已读条目数上界(与 rowCount 分开)
2. `USER/App/Pages/FirmwareUpdate/FirmwareUpdate.cpp`
   - 新增平台隔离 include `wdg.h`(`#if !defined(_WIN32)`,模拟器无 wdg 桩)
   - 新增 `TXT_SCAN_LIMIT` 宏(纯 ASCII 提示文字,避免字体可用性问题)
   - `LoadFiles()` 重写:
     a. 新增 `uint16_t scanCount` 计数器,统计每次 `lv_fs_dir_read` 调用
       (含被过滤的),到 `SCAN_MAX` 即 break,消除无界遍历
     b. 每 32 次读条目调 `WDG_ReloadCounter()` 喂狗
       (`#if !defined(_WIN32)` 平台隔离),使长扫描不再触发 IWDG
     c. 截断时 `SetBrowserMessage(TXT_SCAN_LIMIT, "")` 提示用户,不静默截断

### 取舍理由

- 方案 1(限制遍历总数):最小改动,直接消除无界遍历根因。
  `SCAN_MAX=256` 的选择依据:ROW_MAX=24 个可见行,每行最多需要扫描
  ~10 个非 .etu 条目(地图瓦片目录),256 足够覆盖正常使用场景;
  即使极端目录(根目录含大量文件)被截断,用户仍可见前 24 项且有提示。
- 方案 2(扫描期喂狗):治标兜底,防止方案 1 上界内的扫描仍超 10s。
  每 32 次读条目喂狗,假设单次 `lv_fs_dir_read` ~50ms(SD FAT 目录遍历),
  32 次 ~1.6s,远低于 10s IWDG 超时,裕度充足。
  直接调 `WDG_ReloadCounter()`(声明在 `wdg.h:33`)而非 `HAL::HAL_Update()`,
  避免 `taskManager.Running()` 重入 LVGL 的风险(会带起其他已注册任务)。
- 方案 3(分帧/异步加载)改动量最大,且方案 1+2 组合已消除根因,不采纳。

## 量化说明(prompt S3.2 要求)

扫描耗时/根目录条目数未做 RTT 插桩量化。理由:
- AC5 构建链因预存问题损坏,无法生成可烧录固件做真机 RTT 插桩
- 但修复方案的上界/喂狗周期裕度可从静态分析说明:
  - IWDG 超时 10000ms(reload 1561/DIV_256/LICK 40kHz ~9990ms)
  - 喂狗周期:每 32 次 dir_read 调一次,假设单次 dir_read ~50ms
    (SD FAT 目录遍历,含 SDIO 事务 ~150us 固定开销),
    32 次 ~1.6s << 10s,裕度 6x+
  - SCAN_MAX=256 上界:256 次 dir_read ~12.8s(理论上界),
    但配合喂狗不会触发 IWDG;实际场景根目录条目数通常 <100
- 真机量化插桩留给主会话在修复 AC5 构建后执行(prompt S3.3 真机自验)
