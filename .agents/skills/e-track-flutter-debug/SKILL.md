# E-Track Flutter Debugging

Keep development feedback cheap, device operations bounded, and conclusions tied
to original observations. This skill does not grant CI, installation, reset,
OTA, publishing, or writes outside the authorized project root.

## Choose The Route

- For source changes, read [development validation](../../../docs/flutter-development-validation.md)
  and the app's AGENTS.md first. No local Flutter/Gradle builds. Use the approved
  development workflow and its current inputs, not a remembered branch-name trick.
- Before USB, BLE or MCU work, read [device sessions](references/device-session.md).
  Keep App installation, user UI actions, transport observation and final device
  verification separate. A green CI job is not an installed or running APK.
- For questions, rejected changes or uncertain permission boundaries, use the
  [agent collaboration contract](../../../docs/agent-collaboration-contract.md).
  Return a recommended direction and a discriminating check, not "investigate".
- On continuation, use the actual thread summary/task context. Do not infer a
  missing conversation from unrelated old logs or the working directory.

## Prepare Before Opening The Device Window

1. Record the authorized root, operation scope, cumulative device quota, retained
   firmware state and real human actions. User-approved internal work does not
   need a new question for every command. Explicit caps and new side effects
   still need a scope decision; combine genuinely new needs into one request.
2. Review the bounded change set, fix related issues together, and batch host
   tests/CI. Prepare the actual APK, immutable firmware package, both collectors,
   post-upgrade extraction and cleanup before starting short-lived workers.
3. Bind the commit, actual CI results on both hosts, APK hash/application ID,
   observation marker, endpoint, device identity and package hash/length. Preserve
   a failed dispatch/install receipt and determine its outcome before retrying.
4. Start the smallest required device window near the user's action. Verify real
   producer records and the downloaded package before inviting one transfer.
   Reserve enough time for transfer, reboot verification, readback and cleanup;
   never shrink those allowances because setup consumed the window.
5. Give one concrete UI instruction when it is actually needed. Do not ask the
   user to install/export files the authorized USB route can handle. During an
   observed foreground OTA, do not ask them to switch to chat to acknowledge it.

## Host Reliability

- Prefer cmd.exe on Windows. PowerShell -NoProfile and TEMP overrides do not
  contain its startup caches. Use isolated Python with `-I -S -B -X utf8` and
  explicit cwd. A small project-local script is safer than a large quoted command.
- Preflight the actual outputs and their parents, including Git metadata,
  child-process home/AppData/temp/cache paths and native debugger logs. Use
  [host_io.py](scripts/host_io.py) for stable-parent path checks and bounded
  atomic replacement. Its default rejects all reparse points, even internal ones.
- Do not repeatedly resolve another process's ephemeral `state.json.tmp` as a
  prerequisite to a read-only USB command. Check the current operation's outputs;
  each writer owns preflight of its own temporary files. A disappearing leaf and
  a Windows extended-path spelling are not proof of a project escape.
- On WinError 5/32/33 during atomic replacement, retry the same fsynced temporary
  file for a bounded interval. Do not recreate a reservation, repeat a device
  command, erase an old pending file, or hide a persistent failure.
- Use owned hidden workers with finite deadlines, one reader per log channel and
  acknowledged readiness/closure. A terminal return or PID alone is not proof.
  Source-pinned running helpers stay immutable; diagnose before replacing them.

## Evidence And Measurement

- Distinguish query-only checkpoints from a finished App snapshot. Preserve the
  exact App-generated bytes and verify its footer, counts, hash, identity and
  loss/error fields. Never manufacture a footer or weaken the query-only parser.
- UI "completed" is corroboration, not final authority. Require fresh post-reboot
  device identity/full raw image hash and the applicable Boot confirmation. Retain
  the target; do not downgrade by App-only flashing across changed BCB state.
- Report download, BEGIN-to-END ACK, apply and reconnect separately. Discovery is
  nested in GATT writes; ACK samples overlap work. Do not sum them as exclusive
  phases or subtract unsynchronized clocks.
- A complete log can still contain unusable latency samples. Early ACKs, missing
  P99 samples, unknown UART/staging timing and non-reference package sizes stay
  explicit. A successful small transfer is not stability or throughput acceptance.
- Batch likely candidate implementations and tests, not every imaginable idea.
  Use a fixed input matrix, single-factor controls or a declared factorial design,
  and a small screening stage before expensive repeats. One physical link remains
  serial; comparison packages and initial durable/version state must be equivalent.

## Validate This Skill

From the verified project root, run the self-test with an explicit absolute root
and a fresh output directory under that root:

    python -I -S -B -X utf8 .agents/skills/e-track-flutter-debug/scripts/selftest.py --root ABSOLUTE_PROJECT_ROOT --out PROJECT_LOCAL_FRESH_OUTPUT

The test performs no CI, ADB, J-Link or OTA operations. It preserves its local
fixtures and tests actual Windows file sharing when running on Windows.
