## 五、审查中发现的、需要写进结论的三件事

1. **本轮 CI 证据由验收会话自己推送产生**，取证方与被验方同源。可核部分：分支端态
   相对基线在 `Libraries/`、`USER/`、`boot/`、`MDK-ARM_F435/` 四个红线目录上 diff 为空，
   每次注错/还原提交恰含一个文件。不可核部分是会话自述本身。
2. **两条触发器反证的提交不在任何分支上**（临时 `master` 已按计划删除）。门禁复算不
   依赖 git，故不受影响；受影响的是人工按 SHA 追溯。
3. **P3-6 的冻结 harness 现为红**，红因唯一且可归属（本卡改了它钉死的步骤名）。不阻断
   本卡，不回改 P3-6 冻结字节。

## 六、本轮修掉的两处**验收方自身**缺陷

治理与自检机制这轮抓到的都是我方的错，值得单列：

1. CI 证据核验器的双向鉴别力自检，在真实 run 号回填后常量字面替换全部失配，退化为
   「11 个变异全红、但红因清一色是证据文件缺失」的零鉴别力状态。全红看起来像鉴别力，
   实际上此时删掉任何一条判据自检照样全红。
2. 派工书 v2 的写入脚本吞掉了 `## 任务类型` 章节标题，被 `tests.ota.test_acceptance_bundle`
   当场抓红。门禁抓的是验收方的错，不是实现方的——这正是它该有的行为。

两处均已修复并复跑至绿（308 项核对零失败 / 11 类变异全部红在对应关键词 / 治理 65/65）。
